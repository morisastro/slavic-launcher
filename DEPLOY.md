# Deploying the Slavic Launcher Backend

Your launcher needs a public backend so all users can access news, servers, and redeem codes.
Pick one of the free options below. **Fly.io is recommended** because it offers persistent storage (SQLite data survives redeploys).

---

## Option A: Fly.io (Recommended — free + persistent storage)

Fly.io gives you 1 VM + 1GB persistent volume on the free tier. Perfect for PocketBase + SQLite.

### Prerequisites
- GitHub account (to push your code)
- [flyctl CLI](https://fly.io/docs/hands-on/install-flyctl/)

### Steps

1. **Push your code to GitHub**
   ```bash
   git remote add origin https://github.com/<you>/slavic-launcher.git
   git push -u origin main
   ```

2. **Login to Fly.io**
   ```bash
   flyctl auth login
   ```

3. **Launch the app** (from the repo root)
   ```bash
   flyctl launch --no-build --dockerfile backend/Dockerfile
   ```
   - Choose a name: `slavic-backend` (or anything)
   - Choose a region near you
   - When asked about volumes, say **yes**

4. **Create a persistent volume** (if not created in step 3)
   ```bash
   flyctl volumes create pb_data --size 1
   ```

5. **Set secrets** (admin credentials for PocketBase)
   ```bash
   flyctl secrets set PB_ADMIN_EMAIL=you@example.com PB_ADMIN_PASSWORD=YourSecurePass123
   ```

6. **Deploy**
   ```bash
   flyctl deploy
   ```

7. **Verify**
   ```bash
   curl https://slavic-backend.fly.dev/api/health
   ```
   Should return `{"code":200,...}`

8. **Update the launcher**
   Open `electron/services/settings.ts` and set `backendUrl` to your Fly.io URL:
   ```ts
   backendUrl: "https://slavic-backend.fly.dev",
   ```
   Or just change it in the launcher's Settings tab at runtime.

### Admin panel
Visit `https://slavic-backend.fly.dev/_/` and login with your `PB_ADMIN_EMAIL` / `PB_ADMIN_PASSWORD`.

## Option B: Render.com (free, but data resets on redeploy)

> **Warning:** Render's free tier has no persistent disk. Your SQLite data resets on every deploy.
> Use this only for testing, or upgrade to a paid plan ($7/mo) for a persistent disk.

### Steps

1. Push code to GitHub
2. Go to https://render.com → New → Web Service → connect your repo
3. Render reads `render.yaml` automatically
4. Set env vars: `PB_ADMIN_EMAIL`, `PB_ADMIN_PASSWORD`
5. Deploy

## Option C: Your own PC + Cloudflare Tunnel (free, always-on if PC is on)

Good for development or a small community.

### Steps

1. Start PocketBase locally:
   ```bat
   cd backend
   start.bat
   ```

2. Install [cloudflared](https://github.com/cloudflare/cloudflared/releases)
3. Create a tunnel:
   ```bash
   cloudflared tunnel --url http://127.0.0.1:8090
   ```
4. You'll get a URL like `https://random-words-xyz.trycloudflare.com`
5. Set that URL in the launcher's Settings → Backend URL

> Note: The URL changes every time you restart cloudflared (free tier).
> For a stable URL, register a domain + use `cloudflared tunnel route`.

---

## Option D: Koyeb (free, but no persistent storage)

Similar to Render — free tier but data resets on redeploy. Not recommended for SQLite.

1. Go to https://app.koyeb.com
2. Create service from GitHub repo (reads `koyeb.yaml`)
3. Set env vars
4. Deploy

## Managing content after deploy

All content is managed via the PocketBase admin panel at `https://your-url/_/`:

- **News** — Add posts shown on the launcher home screen
- **Servers** — Add featured Minecraft servers
- **Cosmetics** — Define cosmetic items (capes, hats, etc.)
- **Redeem codes** — Generated by the Discord bot or created manually
- **Users** — Created automatically when players redeem codes

## Backups

- **Fly.io:** `flyctl ssh sftp get /pb/pb_data/data.db ./backup-$(date +%Y%m%d).db`
- **Local:** Copy `backend/pb_data/data.db`
- **Any:** Use the admin panel → Export
